처음 시작하기기존 자료 이어쓰기논문 읽기두 노트북 동기화기능 업데이트문제 해결

1. 처음 시작하기

  1. Chrome 또는 Edge에서 위의 내 논문 서재 주소를 엽니다. GitHub 저장소 화면과는 다른 주소입니다.
  2. 내 서재 연결 창에서 GitHub 토큰을 입력합니다. 계정과 저장소는 이미 지정되어 있습니다.
  3. 개인 노트북에서는 이 브라우저에 토큰 기억하기를 켜고 GitHub 연결을 누릅니다.
  4. 상단에 GitHub 연결됨이 표시되면 준비가 끝났습니다.
  5. 다른 노트북에서도 같은 주소를 열고 최초 한 번 연결합니다.
기존 HTML이나 로컬 미리보기에서 인증했더라도 웹사이트 주소에서는 토큰을 한 번 다시 입력해야 합니다. 브라우저가 주소별로 인증 정보를 따로 보관하기 때문입니다. 논문을 새로 등록해야 한다는 뜻은 아닙니다.

GitHub Pages는 HTML 앱을 웹 주소로 제공하는 서비스입니다. 이 앱의 GitHub Pages 설정은 이미 완료되어 있으므로 직접 저장소를 만들거나 배포 설정을 할 필요가 없습니다.

2. 기존 자료 이어쓰기

기존 앱에 ‘GitHub 연결됨’이 표시되어 있었다면

기존 앱에서 GitHub 저장됨을 확인한 뒤 웹사이트로 이동하세요. 같은 비공개 저장소에 연결하므로 PDF·인용 정보·하이라이트·메모를 그대로 불러옵니다. 따로 옮길 파일은 없습니다.

기존 앱을 로컬 모드로 썼다면

  1. 원래 쓰던 HTML을 같은 노트북·같은 브라우저·같은 파일 경로에서 엽니다.
  2. 저장소 설정 → GitHub 연결을 완료합니다.
  3. 다시 저장소 설정 → 로컬 서재를 GitHub로 복사를 누르고 완료될 때까지 기다립니다. 연결만 하면 로컬 자료가 자동 업로드되지는 않습니다.
  4. 새 웹사이트에서 논문과 메모가 보이는지 확인합니다.

기존 HTML은 새 사이트에서 자료가 보이는 것을 확인할 때까지 보관하세요. 로컬에만 있던 자료는 브라우저의 사이트 데이터를 지우면 사라질 수 있습니다.

3. 논문 추가하고 읽기

  1. PDF 추가로 파일을 선택합니다. 여러 PDF를 함께 추가하거나 서재로 끌어다 놓을 수 있습니다.
  2. 편집에서 제목·저자·출판처·연도·DOI·요약·태그·BibTeX를 정리합니다.
  3. 논문 제목을 눌러 PDF를 엽니다.
  4. 문장을 드래그하고 원하는 색을 선택합니다. 메모 창에 생각을 적고 완료를 누릅니다.
  5. 약 1.2초 뒤 자동 저장되며, 상단에서 GitHub 저장됨을 확인합니다.

기존 하이라이트를 클릭하면 메모·색상을 수정하거나 삭제할 수 있습니다. 오른쪽 메모 목록에서 항목을 누르면 해당 위치로 이동합니다. 스캔본은 선택 가능한 OCR 텍스트가 있어야 하이라이트할 수 있습니다.

원본 ↓는 원래 PDF를 받는 기능입니다. 하이라이트는 별도 JSON으로 저장되므로 다운로드한 원본 PDF에 합쳐져 있지 않습니다.

4. 두 노트북에서 이어 읽기

노트북 A에서 저장 → 비공개 GitHub 저장소 → 노트북 B에서 확인
  • 앱을 열면 최신 논문 목록을 불러옵니다.
  • 다른 창에서 앱으로 돌아오면 변경을 확인합니다. 연속 확인은 최소 5초 간격으로 제한합니다.
  • 앱이 화면에 열려 있으면 30초마다 목록과 현재 논문의 하이라이트·메모를 확인합니다.
  • 작성 중인 메모, 저장 중인 변경, 열린 편집 창, 선택 중인 PDF 텍스트가 있으면 자동 반영을 잠시 미룹니다.

노트북을 바꾸기 전에 GitHub 저장됨을 확인하세요. 두 기기 모두 인터넷에 연결되어 있어야 합니다. 같은 논문을 동시에 편집하면 마지막 저장이 우선하므로, 한쪽에서 저장을 마친 다음 다른 쪽에서 이어 읽는 방식이 좋습니다.

5. 기능을 추가하거나 바꾸고 싶을 때

이 대화에 변경할 기능을 알려주세요. 요청에 따라 앱을 수정·검증한 다음 GitHub Pages에 배포할 수 있습니다. 배포가 끝나면 두 노트북에서 브라우저 새로고침만 하면 됩니다. 기존 논문과 메모는 같은 비공개 저장소에 남습니다.

무엇이 바뀌나요?사용자가 할 일
논문·인용 정보·하이라이트·메모앱에서 저장합니다. 다른 노트북에 자동 반영됩니다.
앱 기능·화면 디자인수정본이 배포된 후 웹페이지를 새로고침합니다.
데이터 저장 형식이 크게 바뀌는 기능업데이트 작업에 백업·호환성 확인 또는 데이터 이전도 포함해야 합니다.

상단의 ↻ 새로고침 버튼은 논문 목록 갱신용입니다. 새 앱 버전을 받을 때는 브라우저의 새로고침을 사용하세요. 이전 화면이 계속 보이면 저장 완료 후 Windows에서 Ctrl + Shift + R, Mac에서 Command + Shift + R을 누르세요.

직접 앱을 업데이트하려면
  1. 공개 앱 저장소를 엽니다.
  2. 수정·검증한 index.html을 저장소 루트의 기존 파일 대신 올리고 main 브랜치에 커밋합니다.
  3. Actions에서 Pages 배포 완료를 확인합니다.
  4. 사이트를 새로고침합니다. 배포에 몇 분 걸릴 수 있습니다.

로컬 컴퓨터의 HTML만 수정하면 사이트는 바뀌지 않습니다. 공개 저장소에는 앱·가이드만 올리고 토큰·PDF·논문 데이터 파일은 올리지 마세요.

6. 두 저장소의 역할

저장소역할공개 여부
paper-grove앱 화면과 사용 가이드. 기능 업데이트는 여기서 배포합니다.공개
paper-grove-libraryPDF 원본, library.json, 하이라이트·메모 JSON. 삭제하지 마세요.비공개

웹사이트와 앱 소스는 다른 사람이 볼 수 있습니다. 논문 데이터는 비공개 저장소의 접근 권한이 있는 토큰으로만 읽습니다. 토큰은 앱 소스에 포함하지 않고 각 브라우저에 보관합니다.

7. 문제 해결

앱에서 토큰을 다시 요구해요.

새 주소·브라우저·기기, 시크릿 창, 브라우저 데이터 삭제 후에는 다시 입력해야 합니다. 토큰이 만료되었거나 폐기되면 저장소 설정에서 새 토큰으로 갱신하세요.

토큰은 어디서 다시 만드나요?

GitHub 토큰 발급 화면에서 fine-grained token을 만들고, 소유자 shkim0824 → Only select repositories → paper-grove-library만 선택하세요. Repository permissions → Contents: Read and write 권한을 지정합니다. 일반 사용에 공개 앱 저장소나 계정 관리자 권한은 필요하지 않습니다.

논문이 없거나 최신 메모가 안 보여요.

상단이 GitHub 연결됨인지 확인하세요. 로컬 모드는 별도 서재입니다. 작성한 쪽의 저장 완료를 확인하고, 편집 창을 닫은 뒤 잠시 기다리거나 목록을 새로고침하세요. 이전 HTML의 로컬 자료라면 위의 복사 절차가 필요합니다.

저장 실패 또는 401·403·404가 나와요.

인터넷, 토큰 만료, 비공개 저장소 접근 및 Contents 쓰기 권한을 확인하세요. 오류가 난 메모는 재시도하거나 하이라이트 JSON 내보내기로 보관할 수 있습니다.

사이트가 404로 나와요.

앱 저장소의 Settings → Pages에서 Deploy from a branch → main → /(root)인지 확인하고, Actions의 배포 완료를 기다리세요. 논문 데이터 저장소의 설정은 바꿀 필요가 없습니다.
